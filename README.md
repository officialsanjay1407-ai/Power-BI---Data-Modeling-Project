# Power BI Sales Data Modeling & Analytics Project

## Project Overview

This project focuses on building a structured and scalable data model for a sales dataset using Microsoft Power BI.

The primary objective was to transform raw sales data into a well-organized analytical model by performing Data Exploration, Cleaning, Transformation, Data Modeling, DAX calculations, and Row-Level Security implementation.

---

## Objective

The main objective of this project was to:

- Explore and understand raw sales data
- Clean and transform data using Power Query
- Design a structured data model using fact and dimension tables
- Establish relationships between tables for efficient analysis
- Create calculated columns and DAX measures
- Implement Row-Level Security (RLS) to control data access
- Build a reliable foundation for sales reporting and analysis

---

## Problem at Hand

The raw sales data consisted of multiple tables containing different types of business information.

Working directly with unstructured or poorly connected data can lead to:

- Data inconsistencies
- Incorrect relationships
- Difficulties in performing analysis
- Duplicate or redundant information
- Inefficient reporting
- Challenges in maintaining data security

Therefore, the key challenge was to transform the available sales data into a structured analytical model that could support reliable business reporting and analysis.

## Project Steps

### 1. Data Loading

Loaded the sales dataset into Microsoft Power BI and reviewed the available tables and fields to understand the structure and characteristics of the data.

### 2. Data Exploration, Cleaning & Transformation

Used **Power Query** to explore, analyze, and clean the data.

The data preparation process involved examining the available fields and ensuring that the data was appropriately structured for modeling and analysis.

Pivot and Unpivot was used to transform the table data into required format.

### 3. Data Modeling

Designed a structured data model by separating the data into:

- **Fact tables** containing transactional/business data
- **Dimension tables** containing descriptive attributes

Relationships were then established between the relevant tables to create a connected analytical model.

### 4. Galaxy Schema

Applied relationships between multiple fact and dimension tables to build a **Galaxy Schema (Fact Constellation)** data model.

This structure allows multiple business processes/fact tables to share common dimensions and supports flexible analytical reporting.

### 5. DAX Calculations

Created:

- Calculated columns
- DAX measures

These calculations were used to derive additional analytical information from the underlying data and support business reporting.

### 6. Row-Level Security

Implemented **Row-Level Security (RLS)** in Power BI to restrict data access based on defined user-level requirements.

This demonstrates the application of data security concepts within a Power BI reporting environment.
